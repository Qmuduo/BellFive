# BellFive 双方牌库计数与收牌动画设计

日期：2026-10-05

## 目标

在当前左右并排的对局布局中，让双方 draw pile 剩余张数一样醒目，并让加牌、减牌和收牌动画落到当前布局里的实际牌库位置。用户选择将双方数量并排放在底部操作区。

## 当前实现

- `GameScreen` 底部深色操作区只突出本地玩家的 draw pile 数量。
- `GameCard` 在桌面左右两张牌下方同时显示 draw pile 数量和桌面 played pile 数量，因此对手数量虽存在，但字号小且与桌面牌数混在一起。
- `CardTransferFly` 使用旧的上下牌区固定偏移；新界面将本地玩家固定在左侧、对手放在右侧，底部操作区固定在屏幕下方，旧坐标不能对齐到当前牌区。
- 服务端快照已提供双方的 `drawCount` 和 `playedCount`；动画事件提供 caller、结果和 `movedCardCount`。无需改变游戏规则或网络协议。

## 方案

### 双方牌库计数

- 在底部深色操作区的身份栏里并排显示本地玩家和对手的 draw pile 计数。两项使用相同的视觉权重，顺序固定为“我、对手”，并从快照中按真实 `PlayerId` 读取数据。
- 对局进行时，桌面牌面保留 `TABLE N` 的 played pile 数量；牌面下方不再重复 draw pile 数量。
- 完成本局后，底部操作区改为重赛区，双方 draw pile 数量仍能在桌面牌面上查看，避免结束状态丢失计数。
- 计数在 320px 窄屏和紧凑高度下保持可读，不挤压翻牌和按铃按钮。中英文均提供清楚的可见短标签和无障碍名称。

### 转牌动画与反馈

- 将双方计数控件和两侧桌面牌区作为动画锚点，测量它们在同一屏幕坐标系中的位置；飞牌覆盖层根据实时位置计算运动路径，不依赖固定的上下偏移。
- 错误抢铃时，最多显示 5 张牌背飞行动画，从 caller 的牌库计数飞向对手计数；`−N` 和 `+N` 分别靠近出牌方与接收方计数。`N` 使用服务器事件中的实际 `movedCardCount`；为 0 时不显示牌数变化或飞牌。
- 正确抢铃时，牌从左右两侧可见的桌面牌区飞向抢铃玩家的牌库计数；增加提示显示在赢家计数旁。桌面实体规则及事件计数保持不变。
- 所有位置先映射到当前设备上本地玩家在左、对手在右的 UI 锚点，再根据事件中的真实玩家 ID 选择起点和终点。
- 动画覆盖层不拦截触摸；滚动、紧凑布局、双方本地座位不同以及设备安全区变化都不会改变目标对应的玩家。

## 备选方案

保留双方计数在各自桌面牌面下方，只放大对手计数。该方案改动较小，但继续把双方数量分散在桌面和底部操作区，未达到用户选择的并排观察方式，因此不采用。

## 验收标准

1. 对局中底部操作区同时显示双方当前 draw pile 张数；本地玩家永远排在前面，数量随服务器快照变化。
2. 桌面左右两侧继续显示对应玩家的 played pile 张数，且 active 视图不重复显示 draw pile 数量。
3. 对局结束时仍可查看双方 draw pile 张数。
4. 错误抢铃的减牌/加牌提示和飞牌分别落在实际出牌方与收牌方计数附近；`movedCardCount === 0` 时不出现变化动画。
5. 正确抢铃的飞牌从两侧桌面牌区飞向真实 caller 的计数，身份映射在本地玩家为 A 或 B 时都正确。
6. 布局适配 320px 宽设备、紧凑高度和中英文界面；动画层不遮挡交互。
7. 不更改游戏规则、服务端状态或网络协议。
