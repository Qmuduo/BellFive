# BellFive 微信小游戏 Canvas 端设计

## 目标

在现有 Expo/Web 与 Taro 小程序之外，新增一个可由微信开发者工具按“小游戏”类型加载的 BellFive 客户端。小游戏构建产物必须在配置的入口目录中包含 `game.js` 与 `game.json`，并实现单机、微信登录与首次自动注册、同账号绑定、公开大厅、好友房、等待与准备、在线牌局及重赛。

## 现状与问题

- 仓库主客户端是 Expo/React Native；共享游戏规则位于 `src/game/`，消息协议与在线客户端位于 `src/network/`，房间与账号服务位于 `server/`。
- `miniprogram/` 是独立 Taro 小程序端。它的构建入口是 `app.json` 和页面路由，项目配置使用 `compileType: "miniprogram"`，不能作为微信小游戏产物。
- 微信小游戏使用独立 Canvas 运行时，不提供 Taro/React Native 页面运行环境。给 Taro 输出添加空 `game.json` 不能完成运行时迁移。
- 本设计新增 `minigame/`，不替换 Expo/Web 或现有 Taro 小程序。

## 方案选择

### 采用：微信小游戏原生 Canvas 2D + TypeScript

新增独立 TypeScript 包，把共享代码打包为小游戏可执行的 `game.js`，并将 `game.json` 与小游戏 `project.config.json` 放入可导入目录。用一个轻量 Canvas 场景/控件层绘制入口、账号、大厅、等待房和牌桌；使用小游戏触摸、键盘、网络、存储、音频与震动 API。共享游戏规则、协议、GameClient 和 AuthClient 尽可能通过依赖注入复用。

优点是没有额外引擎依赖，小游戏入口与平台 API 边界明确，已有服务端和纯 TypeScript 逻辑继续共用。代价是 Taro 页面不能复用，所有小游戏界面、布局和命中区域都要在 Canvas 端实现与验证。

### 不采用：直接把 Taro 产物改成小游戏

Taro 输出依赖小程序页面运行时。把 `compileType` 改为 `game` 或补一个空 `game.json`，只改变开发者工具入口检查，不能提供缺失的 Canvas 游戏启动和 UI 运行时代码。

### 暂不采用：Cocos Creator 重做

Cocos Creator 可提供场景编辑与 UI 组件，并有微信小游戏构建目标，但会增加编辑器、引擎和资源构建流程；现有 Expo/Taro 组件仍需重写，纯规则与协议才可共用。对当前轻量卡牌 UI，Canvas 方案改动边界更小。

## 架构与文件边界

- `minigame/src/entry.ts`：小游戏启动入口，读取屏幕与安全区，创建 Canvas、平台适配器、应用状态机和渲染循环。
- `minigame/src/platform/`：封装 `wx.login`、`wx.request`、`wx.connectSocket`、本地存储、虚拟键盘、音频、震动、分享和生命周期 API；共享域不得直接访问 `wx` 全局。
- `minigame/src/runtime/`：维护小游戏屏幕状态、布局、Canvas 绘制原语、文字换行、触摸命中区域、键盘焦点和弹窗；屏幕至少包括首页、账号/绑定、公开大厅、等待房间、单机牌局和在线牌局。
- `minigame/src/screens/`：每个屏幕只读共享 store 快照并发出动作，不在渲染层重写规则。
- `minigame/src/stores/`：注入小游戏存储与 HTTP/WebSocket 适配器，连接共享 `createGameStore`、账号客户端和资料/设置 store。
- `minigame/src/assets/`：只放 Canvas 端不能用共享矢量/绘制原语替代的小游戏资源；首版沿用 BellFive 的颜色和卡牌语义。
- `minigame/game.json`：小游戏运行时配置，复制到生成目录。
- `minigame/project.config.json`：项目根配置，`compileType` 为 `game`，`miniprogramRoot` 指向生成目录；本机 AppID 通过忽略文件覆盖，不能提交 AppSecret。
- `minigame/dist/`：生成并导入开发者工具的目录，包含 `game.js`、`game.json` 和打包资源，不提交到 Git。
- 根 `package.json` 提供小游戏 build/watch 脚本；小游戏依赖与 Expo/Taro 依赖隔离。

## 运行与身份流程

### 游客单机

小游戏启动后读取本机昵称、头像与设置，并在本地恢复账号会话。没有有效会话时，启动流程会在后台自动调用微信登录并尝试恢复或创建同一 BellFive 账号；这一步只获取登录身份，不请求头像昵称资料授权。无论登录成功与否，游客都可以选择难度并完成本地单机对局，所有规则仍调用共享 `src/game/`。

### 微信登录与跨端账号

- 启动时自动尝试微信登录；有效会话会复用，登录请求进行中时其他联网入口复用同一请求，避免重复调用微信登录。
- 首次微信身份自动创建用户；已绑定身份恢复原用户资料。账号与密码、微信身份绑定与资料同步继续由既有服务端负责。
- 绑定已有用户名账号时先验证账号密码并确认迁移；仅微信账号可设置用户名和密码，之后 Expo/Web 使用同一账号登录。
- 账号令牌只保存在当前设备安全边界内的小游戏本地存储；渲染层不得输出密码、AppSecret、临时 code 或完整令牌。
- 账号资料页通过用户主动点击小游戏原生用户信息按钮，单独获取微信昵称；用户确认后仅把昵称写入 BellFive 账号资料，通过现有资料接口同步到 Expo/Web。取消、拒绝或昵称不可用时保留手动编辑能力，不影响微信身份登录。

### 在线房间

- 登录后由共享 GameClient 通过小游戏 WebSocket 适配器认证连接。
- 创建/加入好友房、公开大厅刷新、申请/审批、准备、翻牌、抢铃、断线重连、离开和重赛均使用现有消息协议。
- 玩家 ID、昵称、头像由服务端认证会话决定，Canvas 只展示共享 store 的服务端快照。
- 大厅、好友房和其他联网操作要求有效会话；登录失败、会话过期或服务不可用时保留访客单机，账号页可手动重试，不伪造已登录状态。

## Canvas 交互与视觉

- Canvas 使用逻辑像素布局，根据窗口尺寸和安全区换算坐标；屏幕方向为竖屏。
- 绘制与触摸命中区域共享同一布局计算，避免按钮视觉位置和实际点击区域偏移。
- 牌面保留当前 BellFive 水果符号、铃铛、双色牌堆、轮次、倒计时、玩家状态和最近抢铃反馈；规则结果以共享 store/服务端快照为准。
- 账号文字输入使用小游戏支持的键盘 API；密码字段遮蔽输入，关闭键盘时保留已输入内容。若平台键盘 API 失败，显示可恢复提示，不提交残缺凭据。
- 卡牌翻转、铃铛反馈和牌堆移动采用轻量 Canvas 动画；音频或震动 API 不可用时只降级反馈，不影响动作。
- 视觉基线沿用 `src/theme/gameColors.ts` 与现有小程序页面的米白背景、圆角卡片和橘色主操作；不引入新设计系统。

## 配置与安全

- `project.config.json` 中仅记录小游戏开发者工具设置和公开占位 AppID；实际 AppID 放入忽略的 `project.private.config.json`。
- 微信 AppSecret 仅由 Node 服务环境变量读取，不进入小游戏 bundle、配置、日志或文档。
- 小游戏服务地址使用构建时的 HTTPS/WSS 配置。开发者工具本地调试可用本机开发配置；真机/发布前必须使用设备可达地址并在微信平台配置合法域名。
- 如果用户现有 AppID 注册类型不是微信小游戏，开发者工具的小游戏预览或 `wx.login` 可能无法按预期工作；需在小游戏账号配置好对应 AppID 和服务端密钥后再做真实身份联调。本地游客单机和模拟界面不依赖该外部条件。

## 错误状态

- Canvas 或启动配置不可读：启动画面显示可辨认的初始化错误，不留下白屏。
- 屏幕尺寸、触摸事件或键盘能力缺失：提供降级布局/错误提示，游戏规则仍保持可访问。
- 启动微信登录失败：在首页保留游客单机，并显示可恢复的账号服务错误；账号页可手动重试。
- 微信昵称授权取消、拒绝或返回空昵称：不修改账号资料，允许继续手动编辑昵称。
- HTTP、WebSocket、认证或资料同步失败：保留本地单机入口；在线动作可以重试，认证失败要求重新登录。
- 房间拒绝、满员、申请取消、断线与房间结束：展示协议中的状态和下一步操作，不在客户端推演服务端结果。

## 验收范围

1. 根目录可独立安装/构建小游戏包；构建后 `minigame/dist/game.js`、`minigame/dist/game.json` 存在且小游戏项目配置的根路径正确。
2. 微信开发者工具以“小游戏”类型导入 `minigame/` 后不再查找缺失的 `dist/game.json`，模拟器能显示 Canvas 首页。
3. 访客在账号服务关闭时可以完成本地单机；音频/震动关闭或缺失不阻塞操作。
4. 使用两个已认证客户端可完成创建房间、申请/审批、双方准备、完整对局、断线恢复和重赛。
5. 微信登录新用户自动建档，回访恢复同一 BellFive 用户；微信与 Expo/Web 用户名绑定后昵称头像跨端一致；冲突不会静默覆盖。
6. 测试失败、服务未配置、键盘取消、过期会话和网络断开时有明确可恢复状态。
7. 记录开发者工具模拟器验证与真机/微信服务验证的边界；若合法域名或小游戏 AppID 不齐，不把真实微信登录报告为已通过。

## 实施顺序

1. 建立独立小游戏包、Canvas 启动器、屏幕/触摸布局层与可导入构建产物。
2. 通过小游戏适配器接入共享存储、HTTP 认证、微信登录、WebSocket 与账号状态。
3. 实现 Canvas 首页、登录/绑定、公开大厅、房间码加入与错误提示。
4. 实现等待房间的申请审批、准备、断线状态、离开与分享。
5. 实现单机与在线牌桌、翻牌、抢铃反馈、结束与重赛。
6. 在开发者工具验证加载和本地单机，再用可用的账号与服务域配置完成在线跨端验收。
7. 更新中文操作说明，清楚区分导入 `miniprogram/` 的小程序包和导入 `minigame/` 的小游戏包。

## 依赖与限制

- 共享游戏规则、消息协议、服务端权威玩法和账号服务保持现状，除非小游戏接口揭示具体兼容问题。
- Canvas 端不引入 React Native、Taro、WXML、WXSS 或浏览器 DOM。
- 不将已有开发者 AppSecret 或任何会话凭证复制进小游戏包或 Git。
- 保留既有确认的 5 项 UI 基线失败记录；小游戏端的验收以本规格的构建、开发者工具和跨端玩法范围为准。
