# BellFive 对局反馈与计时设计

## 目标

在现有双手机好友房对局中，加入明确的铃声与牌面反馈、误按冷却、五分钟限时和可辨认的卡牌图标布局。规则仍由服务端权威执行，两台手机显示同一局面。

## 对局规则

- 每局开始时服务端从固定的 C001–C060 定义洗牌并发给双方各 30 张；卡牌内容不按局随机生成。
- 每张牌最多有一个 Wild Bell。若固定定义中有多铃铛牌，将额外铃铛替换为水果图标，保留卡牌 ID 和每张牌的图标总数。
- 只有双方 playedPile 最上面的牌参与水果数量和 `canRing` 判定；成功抢铃时，双方整个 playedPile 都归胜者所有。
- 铃铛按钮在进行中的对局里始终可按。错误抢铃者向对手交出 drawPile 顶部 1 张牌；不足 1 张时交出现有牌数，不得出现负数牌堆。
- 错误抢铃者必须先成功翻开自己下一张牌，才能再次触发抢铃判定。冷却期间点铃只显示“先出一张牌再抢铃”，不再追加惩罚；对手仍可抢铃。
- 每局限时 5 分钟，从第二名玩家加入、服务端正式开始发牌时启动；重赛重新计时。剩余时间由服务端维护并同步，避免两台手机计时漂移。
- 任一玩家断线导致房间进入连接暂停时，冻结剩余时间；双方重连后从剩余时间继续倒计时。
- 时间到时立即结束对局，并比较双方拥有的总牌数（drawPile 与 playedPile 合计）；牌数多者获胜，牌数相同则平局。结束后不再接受翻牌或抢铃，并提供重赛操作。

## 铃声、震动与结果

- 按下铃铛时，只在按铃者手机上立即播放短促的按压缩放动画并触发本地震动。
- 服务端确认抢铃结果后，两台手机各播放一次相同结果对应的声音：正确时清晰的短促 DING，错误时较低、较短的提示音。按铃者不额外重复播放按压音效，避免连续双响。
- 正确结果使用明显但短暂的震动；错误结果使用较轻的震动。普通翻牌使用轻微反馈。
- 两台手机都显示同步的结果文案，例如 `DING! / Correct Ring`、`Wrong Ring`、`先出一张牌再抢铃` 和超时胜负结果。

## 卡牌视觉与收牌动画

- 卡牌保持白底和清楚的水果 Emoji。图标不再统一居中排成行：1 个居中；2 个对角分布；3 个形成不对称三角；4 个散布在四个区域；5 个采用松散的五点布局。
- 图标位置依据卡牌 ID 和图标数量稳定生成，同一张牌重复渲染时位置不抖动；图标不得溢出卡面，并允许相同水果重复出现。
- 正确抢铃时，两台手机同时显示桌面牌堆向获胜玩家一侧收集的短动画；实际奖励仍包含双方完整 playedPile。
- 错误抢铃时，两台手机同时显示 1 张牌从误按者一侧飞向对手一侧；若误按者只剩 0 张可交，则不播放转牌动画。
- 动画是状态变化的视觉提示，不延迟或改变服务端状态更新，也不阻挡后续合法操作。

## 服务端状态与客户端职责

- 服务端负责 5 分钟截止时间、误按冷却状态、惩罚转牌、获胜者或平局，以及对局结束后的动作拒绝。
- 同步快照包含剩余秒数、各玩家能否再次抢铃、结果事件版本和转牌/收牌动画所需的最小事件信息；不暴露双方 drawPile 的卡牌内容或顺序。
- 每个已接受的铃铛动作只产生一个带递增事件版本的结果事件，客户端按版本播放一次声音和动画，避免普通快照重复时重播。
- 按铃压缩动画和按铃震动只在本地触发；经服务端确认的结果音效和牌移动动画在两台手机各触发一次。

## 界面

- 保留已确认的共享桌面布局：顶部和底部显示双方名字/牌数，中间并排显示双方当前卡牌，底部提供当前设备玩家的出牌按钮和铃铛按钮。
- 在顶部状态区显示 `05:00` 倒计时；对局结束时显示胜者或平局，并沿用房间现有约定由 Player A 发起 `Restart Game` / 重赛。
- Debug Panel 显示回合、剩余时间、双方 drawPile/playedPile 数、可见水果统计、`canRing`、双方铃铛冷却状态和最近结果事件版本。

## 不在本次范围

不加入登录、公开匹配、好友列表、排行榜、商城、皮肤、每日任务、广告、内购或服务端持久化。好友房继续使用既有房间与连接流程。

## 验收重点

- 固定牌组仍为 60 张，洗牌后各发 30 张，每张最多一个铃铛。
- 误按只罚 1 张；冷却只限制误按者，且该玩家下一次成功翻牌后解除。
- 服务端时间到后按双方总持牌数判胜负，平局和已结束动作均能正确处理。
- 正确/错误铃声事件在两台设备各播放一次；本地按压动画和震动不会同步成双方误触动画。
- 卡牌 1–5 图标布局稳定；成功收牌和误按转牌都能在两端显示方向正确的收集动画。
