# BellFive 音效、玩家资料与牌组机会设计

## 目标

让双手机 BellFive 对局的翻牌、抢铃和胜负反馈更清晰，修正得失牌数量提示的位置，为玩家增加可跨对局保留的昵称和预设头像，并在不改变抢铃公式的情况下增加可抢铃牌面对。

## 当前情况

- 固定 C001–C060 牌组中，枚举任意两张不同卡牌的 1,770 种组合，当前有 85 种满足 `canRing`，比例约为 4.8%。这是静态牌面对比例，不代表一整局中每次翻牌的独立概率。
- 翻牌目前只有本地轻震动；正确铃声正常播放，错误铃声则降低音量并裁成短音。
- `tableVersion` 会因翻牌和正确抢铃而增加，不能单独作为翻牌声音事件版本。
- 收牌动画会将牌飞向相应玩家，但数量徽标没有根据实际接收方固定定位；误按转牌也缺少双方得失数量提示。
- 房间快照只标记 Player A/B，没有昵称或头像。当前没有本地资料持久化依赖。

## 用户体验

### 音效

- 每次服务端接受翻牌后，两台手机各播放一次轻短翻牌音。服务端在房间快照中提供独立递增的翻牌事件版本和出牌玩家；客户端按新版本播放，不依赖同时用于正确抢铃的 `tableVersion`。
- 正确和错误抢铃在两台手机上播放完全相同的 `bell.wav`，使用相同音量和完整时长。误按保留现有较轻震动，不再裁短铃声。
- 对局从进行中变为结束时，获胜方本机播放胜利音效，另一方本机播放失败音效。平局不播放胜利或失败音效。初次 `room.session` 快照和重连快照建立音效版本基线，不播放历史结果；只有客户端在线期间观察到本局结束事件才播放。重赛后新的一局可以正常播放。
- 翻牌、铃声、胜利和失败音效都作为本地资源随应用提供，不请求远程音频服务。

### 得失牌数量提示

- 正确抢铃时，所有收来的牌仍按现有规则移入按铃者牌堆；`+N` 数量提示固定显示在该玩家一侧。
- 错误抢铃时，现有惩罚规则不变。实际移出的 N 张牌从按铃者牌堆飞向对手；按铃者一侧显示 `−N`，接收方一侧显示 `+N`。无牌可移时不显示牌数变化，也不播放飞牌动画。
- A/B 两侧映射根据玩家 ID，而非屏幕上的固定左右位置或当前本地玩家身份决定；两台设备得到相同的归属提示。

### 牌组机会

- 保留 `canRing` 公式、60 个固定卡牌 ID、每张 1–5 个图标、每张最多一个铃铛及随机洗牌/30 张对半发牌。
- 只调整固定 `CARD_DEFINITIONS` 的符号组合，不按对局临时随机生成内容。
- 用所有不同 ID 的无序牌对穷举计算规则命中率。目标至少 10%（不少于 177 / 1,770），相对当前 4.8% 至少翻倍；同时保留五种水果的可见度和不同图标数量的多样性。
- 牌组测试继续验证 ID 唯一、卡牌图标数范围、元素合法以及最多一个铃铛。

### 玩家昵称与预设头像

- 在创建/加入房间的入口中提供昵称输入和内置头像选择。v0.1 头像使用游戏主题水果和铃铛图标；不支持相册照片。
- 昵称和 avatar ID 保存在本机，离开房间或重启应用后仍可使用。昵称先去首尾空格，再按 Unicode code point 截断至最多 12 个字符；空昵称显示对应座位的默认名称。预设 avatar ID 固定为 `banana`、`grape`、`pear`、`strawberry`、`peach`、`bell`。服务端只接受这六种 ID，未知 ID 以座位默认头像替换。
- 创建/加入房间请求携带当前资料；服务端将资料绑定到本房间的玩家座位，并在双方的房间快照中提供公开昵称和头像。重连沿用该座位资料。服务端不会将资料保存为跨房间账户，也不引入用户登录。
- 等候界面、双方牌堆信息和游戏桌面均用头像与昵称替换固定的 Player A/B 文案；牌堆和桌面布局继续由 A/B 玩家 ID 决定。

## 技术边界

- 音效播放继续使用 Expo Audio 和本地文件。共享事件用服务端单调递增版本去重；胜负音效用客户端观察到的本局进行中到结束转换触发，并在初次快照时建立基线。
- 玩家资料作为房间会话数据扩展现有协议和 `RoomSnapshot`，由服务端校验；游戏规则状态 `GameState` 不包含展示资料。
- 本机资料使用 Expo 兼容的持久化存储，并由独立 Zustand profile store 提供给入口和房间创建/加入逻辑。
- 牌面对比例使用纯函数/测试直接调用现有 `canRing` 规则，避免复制一份易漂移的判定逻辑。
- 现有倒计时、断线暂停、惩罚冷却、服务端裁定和收牌逻辑保持不变。

## 错误处理与恢复

- 未知头像 ID 在服务端替换为座位默认头像，不渲染任意网络传入图像。
- 昵称为空、仅空格或过长时使用经过截断/回退后的安全名称，不阻止玩家加入房间。
- 音频未加载或播放失败时仍完成游戏动作；声音不可作为游戏动作成功的条件。
- 客户端按事件版本去重；旧房间快照、重连快照及重复 WebSocket 快照不会重复触发翻牌、铃声或胜负音效。

## 不在本次范围

不加入相册头像、头像上传、账号、跨房间云端资料存储、在线匹配、好友列表、排行榜、商城、皮肤、每日任务、广告或内购；不改变抢铃判定公式和错误铃惩罚规则。

## 验收标准

- 每次已接受翻牌在两端各播放一次翻牌音；正确和错误抢铃在两端播放相同完整铃声；一局结束时本机按胜负播放对应音效，重连不重播。
- 正确收牌的 `+N` 出现在收牌者一侧；错误转牌的 `−N` 与 `+N` 分别出现在失牌者和收牌者一侧，牌移动方向正确。
- 固定牌组穷举至少 177 / 1,770 个不同卡牌对可以触发 `canRing`，并继续满足 60 张、唯一 ID、1–5 个图标和每卡最多一个铃铛。
- 昵称和预设头像在本机重启后保留；两端进入同一房间后都能看到双方相同资料；重连维持原资料。
- 前端与服务端类型检查及完整自动化测试通过。
