# 微信小游戏 Android 视觉对齐设计

状态：用户已确认。覆盖全部小游戏页面，并以 Android 端为视觉参照。

## 问题与目标

小游戏功能已可运行，但 Canvas 端把首页、账号页、大厅和等待房间复用为同一种矩形行菜单；对局页也把重要信息压成小段文本。Android 端使用清楚的内容分区、圆角卡片、强调色操作按钮、玩家信息区和牌桌。这些结构差异让两端看起来不像同一款游戏。

本次目标是让微信小游戏的首页、大厅、等待房间、账号页和对局页，在页面结构、颜色、字体层级、控件形态和间距上与 Android 端一致。小游戏继续使用 Canvas 2D。账号、游戏规则、联网协议及现有功能行为保持不变。

## 参考实现与保护范围

- Android 视觉基准：`src/theme/gameColors.ts`、`src/components/RoomEntry.tsx`、`src/components/WaitingRoom.tsx`、`src/components/AuthScreen.tsx`、`src/components/AccountSettings.tsx`、`src/components/GameScreen.tsx`。
- 小游戏适配范围：`minigame/src/screens/` 与其 Canvas 绘制原语。
- 保留 BellFive 的紫色、薰衣草色和青柠绿品牌配色；不改 Android 页面，不改翻译内容，不增加位图素材。
- 保留现有 action ID、store、认证、网络和规则行为。Canvas 绘制的可点击区域必须与视觉控件一致。

## 视觉系统

使用 `minigame/design-model.yaml` 锁定跨页样式。主背景采用 Android 的淡薰衣草色 `#F5F0FF`，白色作为内容卡片底色，薰衣草色作为次级面板，深李紫作为文字和深色操作区，紫色作为主要操作色，青柠绿突出关键游戏操作。边框沿用淡紫色。现有 Android 系统无衬线字体继续作为 Canvas 字体；标题与操作按钮使用重字重，说明和状态文字使用较轻字重。页面按安全区和可用画布尺寸缩放，不把 Android 像素尺寸直接硬编码到小游戏。

共同 Canvas 原语包括圆角面板、主要/次要按钮、标题与状态区、玩家头像/状态行、输入框样式、分隔线和匹配 Android 的卡牌。行菜单不再作为这些完整页面的主布局；分页、错误、加载、禁用与空状态仍保留并沿用原有数据。

## 页面结构

### 首页

参照 Android `RoomEntry`：顶部语言与账号入口、铃铛品牌标记和 BellFive 标题、玩家昵称/头像资料卡、紫色“创建房间”主按钮、青柠色单机入口与难度选择、大厅房间卡片列表，以及房间码输入和加入操作。已有有效账号进入首页时主动订阅并加载开放房间；访客继续使用单机，并显示现有在线登录提示，不静默发起微信登录。窄屏或矮屏允许页面纵向滚动，确保后部房间入口可达。

### 大厅

使用与首页相同的标题和卡片语言。每个开放房间展示房主头像、昵称、房间号和独立的申请加入按钮；刷新、翻页、房间码加入、申请状态和网络错误具有稳定的分区，不能再把整行同时当作房间内容与操作。

### 等待房间

将房间号放入醒目的薰衣草色代码卡；用玩家卡片展示双方头像、昵称、连接与准备状态；房主申请列表使用白色请求卡和分离的同意/拒绝按钮。连接状态独立显示。准备按钮采用紫色主态和青柠色已准备态，分享使用次级卡片按钮，离开使用次级文本操作。

### 账号页

按 Android `AccountSettings` 与 `AuthScreen` 的结构拆分账号摘要、资料编辑、用户名密码表单、微信绑定/转移确认和账号恢复说明。表单使用带标签的卡片输入框、醒目的提交按钮，以及清晰的错误/成功状态。沿用小游戏系统键盘和隐藏密码行为，不改变账号操作协议。

### 对局页

匹配 Android `GameScreen` 的牌桌与底部操作台层级：顶部标题、计时和轻量辅助操作；薰衣草色回合提示条；左右玩家身份/状态面板与当前牌面；底部深李紫玩家信息台、醒目的翻牌按钮与青柠色拍铃按钮；牌堆统计、结果提示和活动记录放在次级区域。结束状态在操作台呈现胜负并突出重赛/准备按钮。

## 交互与适配

- 每个屏幕独立计算版式；共用视觉原语，但不再用同一组行高/布局容纳不同工作流。
- 每个按钮的可触摸矩形跟随实际绘制矩形；按压、忙碌、禁用、错误和成功状态都有可辨识反馈。
- 内容按安全区布局；在常见窄屏和短屏上不遮挡主要操作。长列表通过 Canvas 内分页或可控滚动呈现，不压缩到难以点击的行。
- 保持现有中英文文案与游客单机回退路径。

## 验收标准

1. 五类页面使用锁定的 Android 配色、圆角卡片和明确的标题/状态/操作层级，不再呈现统一的纯矩形行菜单。
2. 小游戏对局具有可辨识的玩家区、卡牌区和底部操作台；翻牌、拍铃和重赛可用。
3. 首页的资料、单机难度、创建房间、大厅、房间码、账号和语言入口都保留且可触达；大厅、准备房间、账号流程的现有能力不回退。
4. 触控目标与绘制位置一致，并在安全区和不同画布比例下有效。
5. 相关 Canvas 绘制/触控测试、小游戏类型检查与构建通过；之后由微信开发者工具模拟器做人工视觉验收。

## 备选方案

- 只统一颜色和圆角：改动较小，但页面仍保持行菜单结构，无法消除主要差距。
- 只重做首页和对局页：先解决最显眼的两个屏幕，但账号、大厅、等待房间仍像另一套应用。
- 推荐方案：五类页面都使用 Android 的信息层级和视觉组件语言，按 Canvas 的屏幕和触控约束分别布局。这与用户确认的全页面范围一致，也能保持两端后续维护上的一致性。
