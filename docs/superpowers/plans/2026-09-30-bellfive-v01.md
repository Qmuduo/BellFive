# BellFive v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a complete, repeatable local two-player BellFive match in one Expo screen.

**Architecture:** Keep a literal 60-card manifest and pure rules/transitions in `src/game/`. Keep Zustand as the UI-facing adapter, and use focused React Native components for the one Expo Router screen. Side effects for animation, Haptics, and Audio stay outside the pure engine.

**Tech Stack:** React Native, Expo, TypeScript, Expo Router, Zustand, React Native Reanimated, Expo Haptics, Expo Audio, Jest with the Expo preset, and React Native Testing Library for screen behavior.

## Global Constraints

- Local two-player prototype only.
- Use exactly 60 fixed card definitions with IDs `C001`–`C060`; shuffle order only.
- Each new or restarted game shuffles and deals exactly 30 cards to each player.
- Only the top card from each played pile contributes to visible fruit and Wild Bell counts.
- A fruit can ring only when its raw count is `<= 5` and `raw count + wildBellCount >= 5`.
- Correct rings collect both complete played piles to the caller's draw-pile bottom and clear the table.
- Wrong rings transfer up to two cards from the caller's draw-pile top to the opponent's draw-pile bottom.
- A ring does not change the turn established by the last flip. A wrong ring does not skip a turn.
- If the player whose turn it is has no draw card when attempting to continue, the other player wins.
- During an active game the A and B ring zones both remain tappable when `canRing` is false.
- Keep one game screen and exclude all online, account, commerce, ad, ranking, task, and skin features.
