# BellFive v0.1 中文操作手册

这份手册用于两位玩家在两部手机上，通过互联网测试 BellFive 好友房。当前版本是本地测试原型：一台电脑运行房间服务并提供临时网络入口，两部手机分别进入同一房间。

## 1. 测试前准备

需要准备：

- 一台 Windows 开发电脑，已安装 Node.js 和 npm，并已取得 BellFive 项目代码。
- 两部可以访问互联网的手机。
- 两部手机都安装了 Expo Go。项目使用 Expo SDK 57；若 Expo Go 提示 SDK 版本不兼容，请先更新 Expo Go。iPhone 用户还需要在 Expo CLI 和 Expo Go 中登录同一个 Expo 账号。
- 电脑安装 `cloudflared`。它会为游戏房间服务创建临时公网地址。
- 电脑和手机在测试期间保持联网；电脑不要休眠。

> 当前完成的是 Android JavaScript bundle 导出，不是可直接安装的 APK。之前的独立 APK 构建被本机 JDK 连接 Google Maven 时的 TLS 握手错误阻断。以下先通过 Expo Go 加载项目进行手机测试。

## 2. 启动房间服务

在项目根目录打开第一个 PowerShell 窗口：

```powershell
npm ci
npm run server:dev
```

第一次运行需要 `npm ci` 安装依赖，之后可直接运行 `npm run server:dev`。看到 `BellFive room service listening at 0.0.0.0:8787` 后，保持这个窗口打开。

在第二个 PowerShell 窗口检查服务：

```powershell
Invoke-RestMethod http://localhost:8787/health
```

正常结果为：

```json
{"status":"ok"}
```

## 3. 同一 Wi-Fi 测试（不需要公网隧道）

如果开发电脑和两部手机连接同一个 Wi-Fi，可以直接在局域网测试，跳过 Cloudflare 和 Expo 隧道步骤：

1. 在电脑运行 `ipconfig`，找到正在使用的 Wi-Fi 适配器下的 **IPv4 地址**，例如 `192.168.1.20`。不要使用默认网关地址。
2. 确保房间服务仍在运行。在另一个 PowerShell 窗口设置电脑的 IPv4 地址并启动 Expo：

   ```powershell
   $env:EXPO_PUBLIC_GAME_SERVER_URL = "ws://192.168.1.20:8787"
   npx expo start
   ```

   将示例 IP 替换成电脑实际的 IPv4 地址。局域网地址使用 `ws://`。
3. 两部手机都用 Expo Go 扫描 Expo 终端里的二维码。
4. 按第 6 节创建房间并加入游戏。

如果 Windows 防火墙询问是否允许 Node.js 通信，允许其在专用网络上访问。若手机仍连接不上电脑，检查两者是否确实在同一局域网；部分路由器开启了客户端隔离，这时可改用下面的异地隧道流程。

## 4. 为异地测试创建临时公网地址

在第三个 PowerShell 窗口运行：

```powershell
cloudflared tunnel --url http://localhost:8787
```

等待命令输出临时地址，例如：

```text
https://example-name.trycloudflare.com
```

记下主机名 `example-name.trycloudflare.com`。游戏客户端需要把它写成 WebSocket 地址 `wss://example-name.trycloudflare.com`。不要把 `https://` 原样填入游戏配置。

保持 `cloudflared` 窗口运行。关闭或重启隧道后，旧地址会失效。

## 5. 启动手机开发版

在第四个 PowerShell 窗口进入项目根目录，填入刚才拿到的地址并启动 Expo：

```powershell
$env:EXPO_PUBLIC_GAME_SERVER_URL = "wss://example-name.trycloudflare.com"
npx expo start --tunnel
```

把示例主机名替换成你当前的 `trycloudflare.com` 地址。环境变量必须在启动 Expo 之前设置；更换地址后也要重新启动 Expo。

命令启动后，终端会显示二维码：

1. Android：打开 Expo Go，点 **Scan QR code** 扫描二维码。
2. iPhone：用相机扫描二维码，并选择用 Expo Go 打开。
3. 两部手机都重复上述步骤，进入 BellFive 游戏界面。

若 `npx expo start --tunnel` 提示缺少隧道依赖，先运行 `npm install --global @expo/ngrok`，再重试启动命令。Expo 隧道负责把项目加载到手机；Cloudflare 隧道负责游戏数据连接，二者都要保持运行。

## 6. 创建房间并开始游戏

1. 玩家 A 在自己的手机上点 **Create Room**。
2. 等待房间码出现，点 **Share Invite**，把六位房间码发给玩家 B。也可以直接口头告诉对方。
3. 玩家 B 在自己的手机输入房间码，点 **Join Room**。
4. 双方进入牌桌后即可开始。Player A 先翻牌。

两部手机显示同一张桌面，但每部手机只能替自己的玩家出牌。操作一方的手机会向服务端发送操作，服务端处理后将新桌面同步给双方。

## 7. 游戏操作

- **FLIP / 点击自己的牌堆**：轮到自己时翻一张牌。每次只能翻一张；不是自己的回合时按钮不可用。
- **RING**：游戏进行期间可以随时按铃，不能抢铃时按下也会产生错误抢铃判定。
- **限时**：第二位玩家加入并开始发牌后，倒计时从 5 分钟开始。时间结束时，双方抽牌堆与已出牌堆中的总牌数较多者获胜；总数相同则平局。
- **抢铃条件**：只统计双方各自当前最上面一张牌。某种水果数量不超过 5，且加上可用的铃铛图标后能达到 5，即可抢铃。铃铛可以代表任意一种水果，也可以不使用；某种水果本身超过 5 时，铃铛不能抵消多出的数量。
- **正确抢铃**：当前可见牌满足规则时，两部手机都会播放正确铃声并显示 `DING! Correct Ring`；按铃玩家收走双方桌面上的全部已出牌。
- **错误抢铃**：两部手机都会播放较轻、较短的提示音并显示 `Wrong Ring`。按铃玩家把自己抽牌堆顶部最多 1 张牌交给对手；如果对手按铃，该玩家仍可正常抢铃。
- **错误后冷却**：误按玩家必须先成功翻出一张自己的牌，之后自己的铃铛才会重新接受判定。冷却期间铃铛仍可按，屏幕会提示先翻一张牌。
- **游戏结束**：轮到一位玩家翻牌、但该玩家的抽牌堆已空时，对手获胜。Player A 可以点 **PLAY AGAIN** 开始新一局。
- **LEAVE**：离开会关闭整间房。另一位在线玩家会回到房间入口；若想继续和对方玩，需要重新创建或加入房间。

## 8. 网络中断与重新开始

- 短暂断网时，牌桌会显示连接暂停，恢复网络后客户端会尝试自动重连。暂停期间五分钟倒计时也会冻结；双方重连后从剩余时间继续。若还想继续本局，请等待重连，不要点 **LEAVE**。
- 房间服务或 Cloudflare 隧道重启后，原来的临时房间可能无法恢复。检查两项服务正常运行，再由玩家重新创建房间并分享新房间码。
- Cloudflare Quick Tunnel 每次启动都会生成临时地址。地址变化后，更新 `EXPO_PUBLIC_GAME_SERVER_URL` 并重新启动 Expo；手机再扫描新的二维码或重新打开项目。
- 房间数据只保存在当前服务进程内。停止服务会清除房间，不会保存未完成对局。
- 临时隧道仅用于测试，会把游戏服务暴露到公网。不要将此配置用于正式运营；把房间码只分享给测试好友。

## 9. 常见问题

### 手机无法打开二维码

确认 Expo 窗口还在运行，并使用该窗口当前显示的二维码。网络限制时使用 `npx expo start --tunnel`。如果 Expo Go 提示 SDK 不兼容，先更新 Expo Go。

### 能进入游戏，但创建或加入房间失败

确认 `npm run server:dev` 窗口还在运行，并确认 `/health` 返回 `ok`。检查 `EXPO_PUBLIC_GAME_SERVER_URL` 是否使用当前 Cloudflare 主机名和 `wss://` 前缀，然后重启 Expo。

### 一方一直看到连接暂停

确认两部手机都有互联网连接，且房间服务与 Cloudflare 隧道仍在运行。若服务被重启，原房间已丢失，需要重新开房。

### 房间码无效或已过期

重新确认六位房间码。如果服务重启过，请让创建者新建房间并分享新码。

### 怎么停止测试

在 Expo、Cloudflare 隧道和房间服务各自的终端按 `Ctrl+C`。关闭这些进程后，临时房间也会结束。

- [ ] 玩家 B 在另一部手机成功加入。
- [ ] 双方看到相同的翻牌结果，且只能替本机玩家翻牌。
- [ ] 分别验证正确抢铃和错误抢铃。
- [ ] 验证断线恢复、离开房间和 Player A 重赛。
- [ ] 一位玩家抽牌堆归零且轮到其翻牌时，另一位玩家看到胜利结果。
