# BellFive v0.1 中文操作手册

这份手册用于测试 BellFive 的 Expo/Web 客户端和微信小程序，包括游客单机、账号资料同步及好友房。当前版本仍需要自行运行服务并配置客户端地址；房间和进行中的牌局保存在服务进程内，账号资料保存在 SQLite 数据库中。

## 1. 测试前准备

需要准备：

- 一台 Windows 开发电脑，已安装 Node.js 和 npm，并已取得 BellFive 项目代码。
- 两部可以访问互联网的手机。
- 两部手机都安装了 Expo Go。项目使用 Expo SDK 57；若 Expo Go 提示 SDK 版本不兼容，请先更新 Expo Go。iPhone 用户还需要在 Expo CLI 和 Expo Go 中登录同一个 Expo 账号。
- 电脑安装 `cloudflared`。它会为游戏房间服务创建临时公网地址。
- 如需预览微信小程序，还需要安装微信开发者工具，并准备已注册的小程序 AppID；真实设备登录还需要服务端配置该小程序对应的 AppSecret 和正式 HTTPS/WSS 域名。
- 电脑和手机在测试期间保持联网；电脑不要休眠。

> 当前完成的是 Android JavaScript bundle 导出，不是可直接安装的 APK。之前的独立 APK 构建被本机 JDK 连接 Google Maven 时的 TLS 握手错误阻断。以下先通过 Expo Go 加载项目进行手机测试。

## 2. 启动房间服务

在项目根目录打开第一个 PowerShell 窗口：

```powershell
npm ci
$env:BELLFIVE_AUTH_DB_PATH = "server/data/bellfive.sqlite"
$env:BELLFIVE_CORS_ORIGINS = "http://localhost:8081"
npm run server:dev
```

第一次运行需要 `npm ci` 安装依赖，之后可直接运行 `npm run server:dev`。看到 `BellFive room service listening at 0.0.0.0:8787` 后，保持这个窗口打开。

账号数据库默认位于 `server/data/bellfive.sqlite`，上面的变量可显式指定本地路径。部署时将 `BELLFIVE_AUTH_DB_PATH` 指向持久磁盘上的稳定路径，并在重新部署时保留磁盘；否则服务重启或换实例后账号、资料和会话会丢失。数据库和 SQLite 的 `-wal`、`-shm` 文件需一起保存。服务从进程环境读取配置，不会自动加载 `.env` 文件。微信登录还需在服务端私密环境设置 `BELLFIVE_WECHAT_MINI_APP_ID` 和 `BELLFIVE_WECHAT_MINI_APP_SECRET`；不要将 AppSecret 写入仓库或客户端配置。

在第二个 PowerShell 窗口检查服务：

```powershell
Invoke-RestMethod http://localhost:8787/health
```

正常结果为：

```json
{"status":"ok"}
```

## 3. 同一 Wi-Fi 测试（不需要公网隧道）

如果开发电脑和两部手机连接同一个 Wi-Fi，可以直接在局域网测试，跳过 Cloudflare 和 Expo 隧道步骤：

1. 在电脑运行 `ipconfig`，找到正在使用的 Wi-Fi 适配器下的 **IPv4 地址**，例如 `192.168.1.20`。不要使用默认网关地址。
2. 确保房间服务仍在运行。在另一个 PowerShell 窗口设置电脑的 IPv4 地址并启动 Expo：

   ```powershell
   $env:EXPO_PUBLIC_AUTH_SERVER_URL = "http://192.168.1.20:8787"
   $env:EXPO_PUBLIC_GAME_SERVER_URL = "ws://192.168.1.20:8787"
   npx expo start
   ```

   将示例 IP 替换成电脑实际的 IPv4 地址。局域网地址使用 `ws://`。
3. 两部手机都用 Expo Go 扫描 Expo 终端里的二维码。
4. 按第 6 节创建房间并加入游戏。

如果 Windows 防火墙询问是否允许 Node.js 通信，允许其在专用网络上访问。若手机仍连接不上电脑，检查两者是否确实在同一局域网；部分路由器开启了客户端隔离，这时可改用下面的异地隧道流程。

## 4. 为异地测试创建临时公网地址

在第三个 PowerShell 窗口运行：

```powershell
cloudflared tunnel --url http://localhost:8787
```

等待命令输出临时地址，例如：

```text
https://example-name.trycloudflare.com
```

记下这次启动分配给你的主机名。账号客户端使用对应的 HTTPS 地址，游戏连接使用相同主机名的 `wss://` 地址。不要把 `https://` 原样填入游戏配置。

保持 `cloudflared` 窗口运行。关闭或重启隧道后，旧地址会失效。

## 5. 启动手机开发版

在第四个 PowerShell 窗口进入项目根目录，填入刚才拿到的地址并启动 Expo：

```powershell
$env:EXPO_PUBLIC_AUTH_SERVER_URL = "https://<current-tunnel-host>"
$env:EXPO_PUBLIC_GAME_SERVER_URL = "wss://<current-tunnel-host>"
npx expo start --tunnel
```

把 `<current-tunnel-host>` 替换成你当前隧道分配的主机名。环境变量必须在启动 Expo 之前设置；更换地址后也要重新启动 Expo。

命令启动后，终端会显示二维码：

1. Android：打开 Expo Go，点 **Scan QR code** 扫描二维码。
2. iPhone：用相机扫描二维码，并选择用 Expo Go 打开。
3. 两部手机都重复上述步骤，进入 BellFive 游戏界面。

若 `npx expo start --tunnel` 提示缺少隧道依赖，先运行 `npm install --global @expo/ngrok`，再重试启动命令。Expo 隧道负责把项目加载到手机；Cloudflare 隧道负责游戏数据连接，二者都要保持运行。

## 6. 创建房间、申请加入并准备开局

1. 每位玩家先在房间入口填写昵称，并从香蕉、葡萄、梨、草莓、桃子或铃铛中选择头像。昵称与头像保存在各自手机上，之后打开游戏仍会保留；不使用相册照片。
2. 玩家 A 在自己的手机上点 **Create Room**。创建的空房会出现在当前运行中的房间服务公开列表中；点 **REFRESH** 可重新加载列表。
3. 玩家 B 可以从 **OPEN ROOMS** 选择房间，也可以输入六位房间码申请加入；两种方式都需要房主审批。
4. 房主在等待房间的 **JOIN REQUESTS** 中点 **APPROVE** 或 **REJECT**。申请人获批后才会进入房间；未获批前可以取消申请。
5. 两位玩家都进入房间后，各自在自己的手机点 **READY**。双方都准备后自动发牌开局，Player A 先翻牌。

两部手机显示同一张桌面，但每部手机只能替自己的玩家出牌。操作一方的手机会向服务端发送操作，服务端处理后将新桌面同步给双方。

## 7. 游戏操作

- **FLIP / 点击自己的牌堆**：轮到自己时翻一张牌。每次只能翻一张；不是自己的回合时按钮不可用。
- **音效**：翻牌时会播放翻牌声；任意玩家按铃后，两部手机都会播放相同铃声；比赛结束时本机播放胜利或失败音效，平局不播放胜负音。
- **RING**：游戏进行期间可以随时按铃，不能抢铃时按下也会产生错误抢铃判定。
- **限时**：双方都点 **READY** 后开始发牌，倒计时从 5 分钟开始。时间结束时，双方抽牌堆与已出牌堆中的总牌数较多者获胜；总数相同则平局。
- **抢铃条件**：只统计双方各自当前最上面一张牌。某种水果数量不超过 5，且加上可用的 Wild Bell 后能达到 5，即可抢铃。Wild Bell 可以代表任意一种水果，也可以不使用；某种水果本身超过 5 时，Wild Bell 不能抵消多出的数量。固定牌组只有一张 Wild Bell，因此双方明牌合计最多出现一个铃铛；牌组也包含同一张牌出现 5 个相同水果的情况。
- **正确抢铃**：当前可见牌满足规则时，两部手机都会播放同一种铃声并显示 `DING! Correct Ring`；按铃玩家收走双方桌面上的全部已出牌，并在自己一侧看到获得牌数 `+N`。
- **错误抢铃**：两部手机也会播放同一种铃声并显示 `Wrong Ring`。按铃玩家把自己抽牌堆顶部最多 1 张牌交给对手，屏幕会在按铃玩家一侧显示 `−N`、对手一侧显示 `+N`；如果对手按铃，该玩家仍可正常抢铃。
- **错误后冷却**：误按玩家必须先成功翻出一张自己的牌，之后自己的铃铛才会重新接受判定。冷却期间铃铛仍可按，屏幕会提示先翻一张牌。
- **牌桌日志**：双方手机同步显示最近 12 条抢铃与得失牌记录；新一局开始时清空。日志会按本机视角显示，例如本人正确抢铃显示“拍铃正确，获得 6 张牌”，对手误按显示“2号玩家拍铃错误，你获得 1 张牌”。
- **游戏结束与重赛**：轮到一位玩家翻牌、但该玩家的抽牌堆已空时，对手获胜。想重赛时双方都要在各自手机点 **PLAY AGAIN**；两人都准备后自动开始新局。任何一方可以在另一方准备前取消准备。
- **修改昵称和头像**：离开房间回到入口后即可修改；新资料会保存在本机，并在下次创建或加入房间时同步给对局中的两位玩家。
- **LEAVE**：离开会关闭整间房。另一位在线玩家会回到房间入口；若想继续和对方玩，需要重新创建或加入房间。

## 8. 网络中断与重新开始

- 短暂断网时，牌桌会显示连接暂停，恢复网络后客户端会尝试自动重连。暂停期间五分钟倒计时也会冻结；双方重连后从剩余时间继续。若还想继续本局，请等待重连，不要点 **LEAVE**。
- 等待开局或等待重赛期间有玩家断线时，双方准备状态都会清除。重连后需要两人重新点 **READY** 或 **PLAY AGAIN**。
- 房间服务或 Cloudflare 隧道重启后，原来的临时房间可能无法恢复。检查两项服务正常运行，再由玩家重新创建房间并分享新房间码。
- Cloudflare Quick Tunnel 每次启动都会生成临时地址。地址变化后，分别更新 `EXPO_PUBLIC_AUTH_SERVER_URL`（`https://`）和 `EXPO_PUBLIC_GAME_SERVER_URL`（`wss://`），重新启动 Expo；手机再扫描新的二维码或重新打开项目。
- 房间数据只保存在当前服务进程内。停止服务会清除房间，不会保存未完成对局。
- 临时隧道仅用于测试，会把游戏服务暴露到公网。不要将此配置用于正式运营；把房间码只分享给测试好友。

## 9. 常见问题

### 手机无法打开二维码

确认 Expo 窗口还在运行，并使用该窗口当前显示的二维码。网络限制时使用 `npx expo start --tunnel`。如果 Expo Go 提示 SDK 不兼容，先更新 Expo Go。

### 能进入游戏，但创建或加入房间失败

确认 `npm run server:dev` 窗口还在运行，并确认 `/health` 返回 `ok`。检查 `EXPO_PUBLIC_AUTH_SERVER_URL` 与 `EXPO_PUBLIC_GAME_SERVER_URL` 是否指向当前服务；远程测试分别应使用 `https://` 和 `wss://`。更换地址后重启 Expo。

### 一方一直看到连接暂停

确认两部手机都有互联网连接，且房间服务与 Cloudflare 隧道仍在运行。若服务被重启，原房间已丢失，需要重新开房。

### 房间码无效或已过期

重新确认六位房间码。如果服务重启过，请让创建者新建房间并分享新码。

### 怎么停止测试

在 Expo、Cloudflare 隧道和房间服务各自的终端按 `Ctrl+C`。关闭这些进程后，临时房间也会结束。

## 11. 账号注册、登录和跨端资料

### Expo / Web 用户名账号

1. 在 Expo 或 Web 的账号入口切换到注册，填写自选用户名和密码。用户名为 3–24 位英文字母、数字或下划线；密码为 8–128 个字符。之后可用相同用户名和密码在 Expo、Web 或已绑定的小程序账号中登录。
2. 已登录后可在账号设置中修改昵称和头像、查看微信是否已绑定，并退出当前账号。已登录资料保存在服务端；同一账号在另一端登录后也会读取这份资料。
3. 游客不登录也能进行单机游戏。公开大厅、创建好友房和输入房间码加入需要账号登录。游客资料只保存在当前客户端设备，不会同步。

### 微信小程序注册与绑定

1. 在微信小程序选择大厅、创建好友房或加入房间时，未登录用户会进入微信授权登录流程。第一次登录成功会由服务端自动创建 BellFive 账号；之后该微信身份会登录到同一账号。若微信登录或服务请求失败，游客单机仍可使用，在线操作可在网络恢复后重试。
2. **把微信身份绑定到已有用户名账号：**先在小程序用微信登录，打开账号页的“绑定已有账号”，输入已有 Expo/Web 用户名和密码。按提示确认转移当前临时微信身份后，微信身份会登录到目标用户名账号；目标账号已有的昵称和头像保持为共享资料。身份已属于另一个用户名账号时，服务端会拒绝绑定，不会覆盖或合并凭据。
3. **给微信账号增加用户名密码：**在已登录小程序的账号页，为仅微信账号设置未被使用的用户名和密码。完成后可在 Expo/Web 用同一组凭据登录。两种绑定方向都完成后，小程序、Expo 与 Web 使用同一账号资料。
4. **重设已绑定账号的密码：**仅当账号已有用户名且绑定了该微信身份时，在小程序账号页输入新密码，并通过重新获取的微信登录凭据确认。未绑定微信的用户名账号没有短信、邮箱或其他首期找回方式；忘记密码后无法自助恢复。仅微信账号需要保持对已绑定微信身份的访问权。

## 12. 导入和配置微信小程序

1. 安装微信开发者工具。在仓库根目录安装依赖并生成小程序包：

   ```powershell
   npm ci
   npm --prefix miniprogram ci
   $env:BELLFIVE_MINI_AUTH_URL = "https://<your-api-host>"
   $env:BELLFIVE_MINI_WS_URL = "wss://<your-room-host>"
   npm run miniprogram:build
   ```

   两个变量是构建时读取的服务地址，不是密钥：`BELLFIVE_MINI_AUTH_URL` 是 HTTP API 的 HTTPS 根地址，客户端会在其后请求 `/auth/...`；`BELLFIVE_MINI_WS_URL` 是房间 WebSocket 地址。请替换为自己实际部署的服务主机名，并在每次更换地址后重新构建。不要把 AppSecret 填入这两个变量。
2. 在微信开发者工具中导入仓库里的 `miniprogram/` 目录。项目入口配置中的 `miniprogramRoot` 指向生成的 `dist/`；公共 `project.config.json` 使用 `touristappid` 占位值。用自己的已注册小程序 AppID 在开发者工具本地设置中打开项目；若工具把本地设置保存到 `miniprogram/project.private.config.json`，该文件已被 Git 忽略，不要提交它。占位 AppID 不能用于正式登录或发布。
3. 微信小程序后台需分别配置：API 主机到 **request 合法域名**，游戏 WebSocket 主机到 **socket 合法域名**。API 使用 HTTPS，socket 使用 WSS，二者都要有有效证书；只添加其中一个不会自动允许另一个。小程序 AppID 与服务端 `BELLFIVE_WECHAT_MINI_APP_ID`、`BELLFIVE_WECHAT_MINI_APP_SECRET` 必须属于同一个已注册小程序，后两项仅设置在服务端私密环境。
4. `BELLFIVE_CORS_ORIGINS` 是 Expo Web 浏览器源站的精确 HTTP(S) 来源列表，与微信后台的 request/socket 域名设置无关。不要用通配符代替 Web 来源配置。`EXPO_PUBLIC_AUTH_SERVER_URL` 与 `EXPO_PUBLIC_GAME_SERVER_URL` 则分别设置 Expo 的账号 HTTP 地址和游戏 WebSocket 地址。
5. 开发者工具的本地调试选项不代表真机或线上验证已完成。真机测试和发布前要使用实际注册的 AppID、服务端 AppSecret、可从设备访问的 HTTPS/WSS 服务，以及后台登记的合法域名；构建时替换所有占位服务地址。
